# 2択切り替えタブ均等化・空状態文言修正 設計

## 目的

- 2択の切り替えタブを左右50%ずつの均等幅にし、選択肢の長さによる見た目のばらつきをなくす。
- ログイン後、終了済み案件だけが非表示になっている空状態の説明を、iPhone幅でも不自然に折り返さない短い2行へ直す。

## 空状態

見出し、アイコン、位置、文字サイズ、色は変更しない。説明文だけを次の2行へ変更する。

1. `終了済み案件は非表示になっています。`
2. `設定から一覧に表示できます。`

既存の共通説明文スタイルを使い、各行を独立した `span` として表示する。

## 2択切り替えタブ

2つの選択肢を持つ既存のセグメント型コントロールへ、共通の均等幅クラスを明示的に付ける。共通クラスは2列のグリッドを使い、各列を `minmax(0, 1fr)` とする。ボタンはコンテナ幅の50%ずつになり、長い文言でも片側だけが広くならない。

対象は次の既存コントロールとする。

- 案件種別: 単発 / 継続
- 表示言語: JA / EN
- 通常案件の終了済み表示: 一覧に表示 / 非表示
- 継続案件の終了済み表示: 一覧に表示 / 非表示
- 個人スケジュール: スケジュール / 要確認
- チームスケジュール: スケジュール / 要確認
- 個人報酬の集計範囲: 個人の報酬 / チーム報酬も含む
- 個人報酬の期間: 今月 / 年間
- チーム報酬の期間: 今月 / 分析
- チーム設定のメール公開範囲
- チーム設定のその他情報公開範囲
- チーム設定の割り振り権限
- チーム設定の削除権限
- チーム予定ペイン: スケジュール / 要確認

## 対象外

- 3択の報酬換算基準と報酬閲覧権限
- 4択の投稿プラットフォーム
- チーム管理の4タブ
- 通常ボタン、確認ダイアログのボタン、画面下部ナビゲーション
- 各コントロールの外枠位置、ページ配置、色、文言、保存値、切り替え動作

## 後方互換性

CSSクラスと空状態の表示文言だけを変更する。保存値、イベント処理、Firestore、同期処理、権限、案件・報酬データには触れない。

## テストと確認

- 実装前に、対象の全2択コントロールが共通均等幅クラスを持つことを確認する失敗テストを追加する。
- 3択・4択・チーム管理タブに均等幅クラスが付かないことをテストする。
- ログイン後の終了済み案件のみの空状態が、承認済みの短い2行を表示することをテストする。
- 既存の全自動テスト、HTML/JavaScript構文検査を実行する。
- iPhoneの狭幅とiPhone 15相当幅で、文字切れ・重なり・不自然な折り返しがないことをブラウザで確認する。
- iOSへWeb資産をコピーして実機ビルドし、接続中のiPhoneで確認できる状態へする。
