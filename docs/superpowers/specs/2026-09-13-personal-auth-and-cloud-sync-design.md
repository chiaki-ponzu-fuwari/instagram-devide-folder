# 個人ログイン・アカウント削除・端末間同期 設計

## 目的

個人機能のログイン、ログアウト、アカウント削除を安全に完了できるようにし、同じGoogleアカウントでログインした別端末へ個人案件を同期する。

## 決定

- ログイン済みの個人データは Firebase の `users/{uid}` 配下を正本とする。
- 端末内の作業データは、ログインユーザーIDごとに分けて保持する。ログアウト後に別の人の個人案件を表示・送信しない。
- 初回ログイン時だけ、クラウドが空で端末の匿名データがある場合にクラウドへ移行する。クラウドにデータがある場合は、クラウドを読み込んで表示する。
- 保存が通信不良で失敗しても、端末再起動後に再送できるよう、未送信の個人ワークスペースをユーザーIDごとに端末へ保存する。
- ログアウトは、未送信保存を短時間待機してから購読を解除し、ログアウト済み画面へ切り替える。待機を超えた場合は端末に再送用データを残す。
- アカウント削除では、Google/Appleの再本人確認を必須とする。Apple ID のトークン連携解除が失敗した場合は、削除を進めず理由を明示する。
- Firebase Authentication のユーザーを削除した後は、同じGoogleアカウントで再ログインできる。古い削除ジョブ・ロックは新規ログインを妨げない。新規アカウントのクラウド領域は空で開始し、端末データを残す選択をした場合のみ初回移行する。

## データ保護

- アカウント削除の成功前に個人クラウドデータも端末データも消さない。
- アカウント切替中は別UIDのローカルデータを混ぜない。
- サーバーの確認済みスナップショットを別端末表示の正本とし、古い端末の未送信データでクラウド記録を消さない。

## 完了条件

1. Google/Appleでログイン、ログアウト、再ログインできる。
2. アカウント削除後、同じGoogleアカウントで新しいアカウントを作成できる。
3. 端末Aで保存した個人案件が、同じログインの端末Bで表示される。
4. オフライン保存を再起動後に再送できる。
5. 既存のチーム管理データや未ログインの個人データを壊さない。
